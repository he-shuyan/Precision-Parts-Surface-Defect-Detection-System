# 精密零件表面缺陷检测系统 1.0 —— PyQt5 桌面版

在网页版（`启动系统.bat` + 浏览器）之外，按项目书要求做的**桌面应用程序**：
界面用 PyQt5 编写，检测算法**完全复用** `detector.py`（一行算法代码都没重写），
`get_engine()` 会自动启用训练好的 YOLOv8 模型，模型不可用时退回经典算法。
全程本机离线处理，图片与检测结果不出本机。

## 一、怎么启动

| 文件 | 用途 |
| --- | --- |
| `启动桌面版.bat` | 正常启动。无黑色控制台窗口，双击即用 |
| `启动桌面版-调试.bat` | 出问题时用。保留控制台，能看到完整报错信息 |

命令行启动也可以，并可直接带上图片或文件夹：

```bat
python\python.exe main.py "D:\某个图片文件夹"
```

启动后：窗口先出现（约 1 秒），右下角显示「检测引擎：正在加载…」，
随后自动变成「检测引擎：YOLOv8 深度学习模型（ONNX 推理）」
（默认走 ONNX Runtime，加载只要 0.3 秒左右；换回 PyTorch 也只需 2～3 秒）。
加载期间画布中央会显示「正在加载检测引擎…」，检测相关按钮是灰的
（状态栏同时说明原因），加载完成后自动恢复可用。

窗口会记住上次的位置、大小、三栏比例、上次打开的目录和上次导入的图片列表，
记录文件是 `output\桌面版设置.ini`，删掉它就等于恢复出厂设置。

## 二、已实现的功能

- **导入图片**：多选文件（Ctrl+O）、整个文件夹（Ctrl+Shift+O，含子目录）、
  把文件或文件夹直接拖进窗口；点「载入演示图片」可一键载入 `demo` 目录的示例图
  （17 张：5 张合成图 + 12 张公开数据集真实图，见第五节）。
- **连续浏览**：上一张 / 下一张按钮、左侧列表单击切换、画布内方向键切换。
- **检测**：`检测当前图`（F5）、`批量检测`（Ctrl+F5）。检测跑在后台线程里，
  界面不卡死；状态栏有 `x/总数` 进度条，`停止检测`（Esc）可随时中止；
  列表里每张图后面直接标出状态：`· 未检测`、`· 3 处`、`· 无缺陷`、`· 失败`
  （绿色=无缺陷，红色=有缺陷；失败时把鼠标停在列表项上可看具体原因）。
  **双击列表项或按回车**即可检测那一张。
- **推理方式**：默认用 `models\defect_best.onnx` + ONNX Runtime 推理
  （不需要 PyTorch，启动快、依赖小）；设环境变量 `DEFECT_ENGINE=pt`
  可改用 `models\defect_best.pt` + PyTorch（走显卡，单张更快），
  设成 `DEFECT_ENGINE=classical` 可强制用经典图像算法做对照。
  两条深度学习路径结果一致（同一批 23 张图逐框比对：框数完全相同，
  18 张完全一致，其余 5 张只有置信度差 0.02～0.07、坐标不差）。
- **结果可视化**：图上画缺陷框 + 类型标签 + 置信度；右侧表格列出类型、置信度、
  位置、尺寸、面积。表格支持点表头排序（按数值排序，不是按字符串），
  隔行变色；**点表格任意一行，画布上对应的框会闪一下并自动滚进视野**。
  某张图没有缺陷时，表格里会明确写「未发现缺陷」。
- **当前用哪个模型一眼可见**：窗口右下角「检测引擎」悬停会显示
  **模型文件名 + 修改时间 + 大小**、置信度阈值与输入尺寸；换模型后不用猜。
  导出的 HTML 报告页眉同样带上模型文件名。
- **导出**：
  - `导出当前标注图`（Ctrl+S）：按原图分辨率导出带标签的 PNG 到 `output\`；
  - `导出检测报告`（Ctrl+E）：导出 HTML 报告（含每张图的标注缩略图与缺陷明细表）
    以及一份 CSV 明细，可直接打印或转 PDF。
  同一张图还没检测就直接点导出，程序会自动先检测再导出，不再弹窗问你。
- **图像查看**：滚轮（或 Ctrl+滚轮）缩放、按住左键拖动平移、双击画布适应窗口、
  画布右下角常显当前缩放比例。

> 交互原则：**只有"会丢数据 / 无法继续"的情况才弹模态对话框**。
> 导出完成、引擎回退、批量检测中的个别失败这类信息，一律走窗口上方的提示条
> （可以随手关掉，也可以点「打开所在文件夹」直接跳到结果目录）和状态栏。

`demo\` 里现在有 17 张演示图：5 张是 `make_demo.py` 生成的合成图，
12 张是 `real_` 前缀的真实零件/钢板照片，取自两个公开数据集：

| 来源 | 张数 | 许可证 | 要点 |
| --- | --- | --- | --- |
| MVTec AD（MVTec Software GmbH） | 7 | CC BY-NC-SA 4.0 | **仅用于教学科研，非商用**；必须署名；本目录中的转存副本同样以 CC BY-NC-SA 4.0 提供 |
| NEU-DET（东北大学） | 5 | 学术研究用途 | 需署名来源；合规提醒见 `demo\SOURCES.md` |

逐张的文件名、数据集内原始文件、原始下载地址与许可证都记在
[demo/SOURCES.md](demo/SOURCES.md)；分发图片时不要把该文件删掉。
图片只做了格式转存（PNG→JPG），未裁剪、未缩放、未修饰。

三点如实说明：

- 这两个数据集都**没有“锈迹”类别**，所以“锈迹”这一类目前只有合成图能覆盖。
- **12 张真实图里有 6 张后来被收进了微调训练集**（`real_01`、`real_02`、
  `real_03`、`real_05`、`real_06`、`real_07`），它们的成绩偏乐观；
  `real_04` 与 `real_08`~`real_12` 这 6 张从未参与训练，才是可信的泛化测试。
- **微调前后效果对比**（同一批图、同一 IoU≥0.3 口径、conf=0.25 未调）：

  | 模型 | 18 个真值框命中 | 误报 | 从未参与训练的 6 张（14 个框） | 合成验证集抽样 80 张 |
  | --- | --- | --- | --- | --- |
  | 微调前（纯合成） | 0 | 40 | 0/14 | 99.4% |
  | **微调后（`defect_best.pt`，当前）** | **13** | **1** | **11/14** | 98.7% |

  也就是说：钢板上的划痕/斑块/麻点现在基本能框住，合格品不再成片误报；
  但小尺寸、低对比的真实缺陷（如 `real_01` 螺母划痕、`real_05` 螺纹损伤）
  仍有漏检，需要继续补真实样本。逐张结果见
  `output\真实图补充记录\真图检测结果.md` 与 `真图检测结果_微调前.md`。

## 六、已经踩过并修好的两个坑（换机器时请注意）

**1）中文路径让 Qt 找不到自己的插件。**
Qt 推算插件目录时会把安装路径按本地编码转换一次，路径里的「大创」「精密零件表面
缺陷检测系统1.0」会变成问号，启动瞬间直接弹窗：

> This application failed to start because no Qt platform plugin could be initialized.

`desktop/qt_boot.py` 里在创建 `QApplication` 之前，用 Python 传入的 Unicode 路径
显式调用 `QCoreApplication.setLibraryPaths()` 绕开这次有损转换，`main.py` 会自动调用。

**2）PyQt5 先于 PyTorch 导入，会让 YOLO 模型用不起来。**
PyQt5 会把 `PyQt5\Qt5\bin` 注册进 DLL 搜索路径，该目录里带着一份较老的
`MSVCP140.DLL`；之后 PyTorch 加载 `c10.dll` 时用到这份旧运行库，直接初始化失败
（WinError 1114）。`detector.get_engine()` 捕获异常后静默退回经典算法，
表现就是"明明训练了模型，界面却在用传统算法"。

解决办法同样在 `desktop/qt_boot.py`：`main.py` 在 `import PyQt5` **之前**先把
System32 里的新版运行库装进进程（`preload_system_runtime()`），按名字解析就只会
命中系统版，Qt 与 PyTorch 相安无事。现在界面右下角会明确显示用的是哪个引擎；
万一模型加载失败，启动后会在提示条里说明原因（不再弹对话框打断你），
点提示条上的「查看详情」或菜单「帮助 → 关于本系统」可以随时回看。

> 补充（2026-10-16）：桌面端默认改成 **ONNX Runtime 推理后完全不导入 torch**，
> 上面这个冲突默认已经不会发生；`preload_system_runtime()` 保留着，
> 是为了有人用 `DEFECT_ENGINE=pt` 切回 PyTorch 时依然安全。
